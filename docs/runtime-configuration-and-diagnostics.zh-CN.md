# 运行配置与诊断

本文说明 NaturalClick Agent 0.4.51 的执行参数、观察压缩策略、模型流式输出和常见排障方法。

## 配置位置

打开 Chrome 侧边栏中的 NaturalClick 设置页，找到 **执行参数** 区域。配置保存在本地 `chrome.storage.local` 中，刷新扩展后仍会保留。

## 执行参数

| 参数 | 默认值 | 范围 | 影响 |
|---|---:|---:|---|
| 最大步数 | `100` | `1-200` | 任务最多执行多少步，防止无限循环 |
| 文本模型单轮超时（秒） | `60` | `8-180` | 每次文本模型规划最多等待多久 |
| 完整观察最大字符数 | `262144` | `7600-1048576` | 完整页面观察上下文的最大字符数 |
| 精简观察最大字符数 | `4200` | `1000-65536` | 精简观察上下文的最大字符数 |
| 触发精简元素数 | `120` | `20-10000` | 页面结构化元素达到该数量后，首轮直接用精简上下文 |
| 触发精简 raw 数 | `80` | `20-10000` | raw 候选达到该数量后，首轮直接用精简上下文 |

点击 **恢复规划默认值** 会恢复文本模型单轮超时和所有观察上下文阈值。

## 观察压缩如何触发

NaturalClick 会先观察页面并生成结构化上下文。规划器可能使用完整上下文，也可能使用精简上下文。

精简上下文的触发条件有三类：

- 文本长度达到 `完整观察最大字符数`。
- 表单字段、动作、弹层、面板、候选等结构化元素数量达到 `触发精简元素数`。
- raw 候选数量达到 `触发精简 raw 数`。

因此，设置 `完整观察最大字符数 = 261600` 后，仍可能在较小文本长度时进入精简上下文。例如进度中出现 `raw=140/80`，说明触发原因是 raw 候选数量，不是文本长度。

## 进度文案怎么看

```text
观察内容较大，使用精简上下文请求模型规划动作（触发：raw=140/80；完整≈15587字，精简≈8409字；元素=93，raw=140；模型=...；最多等待 60 秒）...
```

这条进度包含：

- `触发：raw=140/80`：raw 候选数量 140，阈值 80。
- `完整≈15587字`：完整观察文本长度。
- `精简≈8409字`：精简观察文本长度。
- `元素=93，raw=140`：当前页面观察规模。
- `最多等待 60 秒`：本轮文本模型超时配置。

```text
模型首轮超时，正在压缩上下文重试（原因：首轮完整上下文超时；完整≈...；精简≈...；模型=...；最多等待 60 秒）...
```

这表示首轮完整上下文请求已经超时，规划器正在使用精简上下文再请求一次模型。

## 模型流式输出

文本模型默认使用 OpenAI 兼容的 SSE 流式响应。侧边栏会维护一张 **模型流式输出** 卡片，而不是为每个片段追加新卡片。

卡片会展示：

- 已收到正文字符数。
- 已收到推理摘要字符数，如果模型提供。
- chunk 数量。
- 当前片段预览。

模型完整返回后，NaturalClick 会继续写入最终模型调用卡片，包含请求摘要、响应摘要、模型 thought/reasoning、动作和校验结果。

如果模型接口不支持流式响应，但仍返回普通 JSON，NaturalClick 会回退到普通响应处理。

## 表单校验和重复值处理

Observer 会收集通用字段级校验和页面反馈，包括：

- HTML 原生 `validationMessage`。
- `aria-invalid`、`aria-errormessage`、`aria-describedby`。
- 常见表单错误节点，例如 Element、Ant Design、Naive UI、Bootstrap 风格错误提示。
- toast、alert、aria-live 等全局反馈。

Verifier 在表单提交后会优先看这些反馈。保存后如果弹层仍然打开，并且没有成功提示、页面变化或弹层关闭，就不会把提交误判为成功。

遇到重复、已存在、唯一约束等反馈时：

- 如果能定位到具体字段，Agent 会尝试修正该字段。
- 如果任务明确允许测试值或任意值，Agent 可以生成不冲突的替代值。
- 如果用户明确指定了字段值，且无法安全替换，Agent 会向用户询问新值。
- 如果新错误已经变成格式错误、必填错误等其他内容，Agent 应根据新错误重新规划，而不是继续沿用上一轮重复值策略。

## 常见问题

| 问题 | 可能原因 | 建议 |
|---|---|---|
| 设置了很大的最大观察字数，但仍然压缩 | 命中了元素数量或 raw 候选数量阈值 | 查看进度括号里的 `元素=.../...` 或 `raw=.../...` |
| 规划卡在模型等待 | 模型响应慢、首包慢、或完整上下文太大 | 提高单轮超时，查看模型流式输出卡片是否收到内容 |
| 表单明明保存了但检测失败 | 页面没有明确成功反馈，或者弹层/列表变化不明显 | 导出日志，检查提交后的 `feedback`、字段 `error` 和 DOM 摘要 |
| 已经创建成功却重复创建 | 成功判断证据不足，或者历史状态没有识别到提交完成 | 查看 Verifier 轨迹里的提交证据，补充可观察成功反馈或页面变化日志 |
| 第一次错误是重复，第二次错误变成格式校验 | 新错误必须重新进入模型/工作流判断 | 查看轨迹中最新 `feedback`，确认 Agent 是否读取了新错误 |

## 导出日志时建议包含

排查复杂页面时，导出的日志最好能看到：

- 当前任务文本。
- 每步观察摘要。
- `feedback` 区块。
- 字段 `invalid` 和 `error`。
- 模型请求 diagnostics。
- 模型流式输出卡片。
- 动作执行结果和 Verifier 判定。

如果这些信息不足以定位问题，可以继续增强 Observer 或 Verifier 日志，而不是写站点定制逻辑。NaturalClick 的目标是通用浏览器 Web 操作 Agent。
