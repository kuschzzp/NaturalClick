# 通用网页 Agent 增强路线图

本文记录 NaturalClick Agent 朝非定制化、自主思考型浏览器操作 Agent 演进的近期优化计划。所有改动应服务于通用网页结构，不应依赖具体站点、业务系统、菜单名或表单字段名。

## 第 1 轮：任务意图与导航恢复

目标：让 Agent 在“进入某页面后继续做事”的链式任务里，先准确进入目标页面，再执行页面内动作。

- 清洗导航目标中的流程连接词，例如“进入 X 后创建”“打开 X 之后测试”应把导航目标归一为 `X`。
- 当直接观察和上下文查询都找不到目标菜单时，不重复请求同一上下文，而是受限展开可见的折叠菜单、导航组或更多菜单。
- 上下文空结果需要明确提示模型换成真实页面动作、导航探索或明确失败，而不是继续同 query 空转。
- 保留安全边界：只展开可见且具有导航容器语义的元素，不把输入框、下拉候选、表格操作按钮当导航容器。

本轮验证重点：

- 中文链式任务不会把“后/之后/以后”并进导航目标。
- 后台类侧边栏在目标子菜单未直接可见时，会按可见导航容器有限探索。
- `query_no_match` 不会直接演变成连续上下文请求直到达到内部上限。

## 第 2 轮：单次任务变量与跨标签页回流

目标：让 Agent 能把当前会话内刚获得的信息用于后续网页操作，尤其是跨标签页查询、验证码、临时生成值和外部搜索结果。

- 把外部查询得到的关键值记录为本轮任务变量，例如用户名、验证码、邮箱地址、价格、订单号等。
- 当主任务是创建、编辑或填表时，外部查询页面只提供字段值，不应把查询页总结当作整条任务完成。
- 当表单需要外部查询值时，应把明确的搜索/来源打开到新标签页，保留主表单标签页，方便取值后回流填写和提交。
- 切回主任务标签页后，优先使用已确认的任务变量，避免重复打开或重复查询外部来源。
- 已确认完成的表单任务会把成功填写的字段组合成当前会话 `record_fact`，帮助后续“刚才创建/上次填写”的指代任务。
- 对价格、行情、货币、单位类证据，应优先选择靠近价格/单位上下文的数值，并降低日期、年份、时间片段的优先级。
- 任务变量只在当前侧边栏会话内生效，不做全局长期记忆。

本轮验证重点：

- “用 A 网站的信息去 B 网站注册/填写”的任务能够跨标签页完成。
- 当外部来源标签页已经拿到当前任务变量时，Agent 会先切回已打开的主任务标签页再填写。
- “刚才创建的记录/刚才查询到的值”能在同一会话后续任务中被引用。
- 失败、未确认、校验错误的创建结果不会被当成成功事实。
- 普通 `done(success=true)` 不能单独证明表单任务成功；仍需要提交、弹层关闭、成功反馈或等价页面变化证据。

## 第 3 轮：主流页面设计适配

目标：覆盖更多真实网页布局和组件库，让 Agent 不依赖单一 DOM 形态。

- 导航适配：侧边栏、顶部导航、树形菜单、折叠抽屉、标签页、面包屑、更多菜单。
- 表单适配：抽屉表单、弹窗表单、分组表单、必填校验、异步下拉、占位选择值、级联选择、日期范围选择器。
- 列表适配：横向滚动表格、虚拟列表、分页、接口返回样本、隐藏列、行内操作按钮。
- 反馈适配：toast、alert、字段错误、全局错误、保存成功但弹层未关闭、保存失败但页面局部刷新。
- 规划适配：当观察证据不足时，先补接口/表格/区域证据；当证据已经足够时，收束为动作或结果总结。

本轮验证重点：

- 不同 UI 库的后台、SaaS 控台、内容管理系统和电商后台都能按相同策略推进。
- 搜索测试能先从列表/API 样本推导测试值，再逐项清空和验证。
- 搜索字段在页面重渲染导致 DOM index 改变时，应按稳定 label/type 迁移已测状态，避免重复测试同一字段。
- 创建/编辑任务必须基于提交反馈、页面变化或当前校验状态判断成败。
- 必填下拉/级联字段应把“请选择...”这类可见占位值视为空值，并先展开真实候选面板，而不是猜测选项。
- 必填选择字段存在多个真实候选时，应请求用户确认取值；只有唯一安全候选才能自动选择。
- 日期范围选择器在开始日期和结束日期相同时，应对同一个真实日期候选完成两次选择，支持同日起止范围。
